## What this is

`hmidmismi/yvml`: pnpm + Turborepo monorepo. `@yvml/web` (Next 15, pages router) and `@yvml/studio` (Sanity Studio 6) consume shared `@hmidmismi/*` packages. `chorusworks/monorepo` (DRAM) consumes the same shared repos. The site is bilingual (`/` English, `/es` Spanish).

## What the web app does now

- **Data layer** (`lib/sanity/`): client, GROQ fragments (`groq.ts`), one query file per document type with `defineQuery` constants and generated result types. Verified equivalent to the old queries on the live dataset (84 query/parameter combinations identical).
- **Text** (`lib/text.ts`): every app string in English and Spanish, read with `t('key')` at render time. The design system's own words are Spanish via `UiProvider` in `_app.tsx`.
- **Filtering** (`lib/filters/`, `workshop-listing.ts`, `components/FilterBar.tsx`): a listing is a `ListSpec` (kinds: search, select, multi, toggle, range; sorts; views). State lives in the address: facets in the path (`/workshops/material/adobe/open`, `/workshops/type/glass+metal-casting/closed`), the rest in the query (`?min-price=200&sort=price-low&view=list`). One catch-all page serves the listing and a workshop's own page, so `open`, `closed`, `material`, `type`, `instructor` are reserved. Unknown facets are a 404; different segment order redirects to the canonical one.
- **Incremental static regeneration**: every page except `/sign-in` and the API routes uses `getStaticProps` (`withDraft` in `lib/static-props.ts`, `REVALIDATE` = 60 s) and, for dynamic routes, `onDemandPaths` (generated on first visit). Draft mode bypasses the cache. The preview login moved to `src/middleware.ts` (Node runtime): without a session or the draft-mode cookie it redirects to `/sign-in`. A cached page has no query string, so `?sort=`, `?min-price=` and the like are read in the browser after hydration, and a non-canonical order of path facets redirects without the query. Next step if wanted: an on-demand revalidation webhook from Sanity.
- **Language in the address**: English has no prefix, Spanish is `/es/...`. `/en/...` redirects to the plain address through `netlify.toml` (Next's own redirects loop under `i18n`); that redirect is not verified, as it only runs on Netlify.
- **Dark mode**: `ThemeToggle` (lucide Sun/Moon) was already in the header; the missing piece was `THEME_INIT_SCRIPT` in `_document.tsx`.
- **Keela**: registration forms use `KeelaEmbed` (iframe via `EmbedFrame`). The newsletter signup on `/about/contact` uses `KeelaSignup` (Keela's own embed script) with the address in `lib/keela.ts`. It is the signup form currently on the live home page; confirm it is the newsletter list.
- **Menus** (`lib/menu.tsx`): `menuLinks(items)` makes header and footer links; web addresses open in a new tab with `rel` and an accessible name that says so. Social links are in `lib/social.ts` (text, not icons: lucide has no brand icons).

## Gotchas

- A shell hook rewrites commands through `rtk`; piping `rtk grep` misbehaves (use plain tools in pipes), and a hook-modified command must be re-issued unchanged.
- Headless Chrome does not run animation frames reliably. The mock `lazy/v2/pile/` has a `#settle` URL hash that pre-simulates the physics for screenshots. Playwright runs from `packages/ui` with `executablePath: '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'`.
- The Keela registration forms are hosted pages, not embeddable with Keela's script (it never reveals them); only the signup form works with the script.
